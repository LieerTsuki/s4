## S2 到 S4 的转换和四类摘要

| 对象 | 计算及登记 |
|---|---|
| S2 候选及原始材料文件 | 生产方冻结实际 `candidates.jsonl`、语料/事实证据、converter 代码提交与配置版本。SHA-256 取交付的原始字节。清单记录相对文件路径、字节数、摘要与授权引用。保留文件的换行和 BOM。 |
| 转换后的 v2 `unit` | `case_id` 绑定稳定 `unit_id`，保留来源快照及逐题 revision。题面、难度、草案要点、支撑文档与锚点按固定 converter 映射输出。QA-D1 可回答题声明 `expected_refusal=false`，gold 文档 2/3 与 ranking 0/1 分区，缺少 ranking 时保留空对象。实际 B-2026-11-25 converter 的固定提交、转换规则和输入应由 S2 提供，以独立重跑输出补齐核对。 |
| `contexts[].sha256` | 对该 context 的 `text` 实际 UTF-8 字节计算。多 chunk 及锚点以 converter 冻结的组装顺序、分隔符和定位口径为准。逐个 doc/chunk 另保留与授权原件的关联。 |
| 逐题 `content_sha256` | 对 `validate_envelope` 规范化后的完整单个 `unit` 计算。覆盖 question、gold、contexts、metadata 和适用字段。处理规则包括省略模型可空的 `None` 字段、保留默认值、核验或补算 context SHA-256、移除旧 `match_field`。报告、信封和整包文件另记摘要。 |
| 整包摘要 | 区分外部交付文件的原始字节摘要与 S4 API 用于 `batch_id + source_revision` 幂等核对的整包规范化摘要。二者都保留，逐题 PASS 使用上表的 `content_sha256`。 |

单元字节按固定 Python 序列化生成：`json.dumps(unit, ensure_ascii=False, sort_keys=True, separators=(",", ":"), allow_nan=False).encode("utf-8")`。对象键排序，数组保留原始顺序，保留 Unicode 字符与字段内换行。`0` 与 `0.0` 在不受类型收敛的字段会产生不同字节。数组换序会改变摘要，跨语言运行方以共享字节向量对比结果。首题原始向量 516 字节、`6e21f253…`，规范化向量 716 字节、`859d7e18…`，本轮逐字节复算一致。S3 递补包的另外 11 个 unit 也逐一复算一致。

## 验证 ID 和台账

- 推荐 `validation_id` 在**同一可信 S3 签发方 `issuer_id` 下跨批次、来源和运行唯一**。每条验证绑定 `(batch_id, source_revision, unit_id, unit_revision, content_sha256, validation_id)`，附判定及验证轮次。历史中同一签发方、同一 ID 对应相同绑定和判定时可幂等复核。内容修订后产生新 revision 和新验证 ID。签发方实际标识及历史覆盖范围须由双方签认。
- **S2 候选冻结台账 `candidates-freeze.json`** 由授权 S2 路径提供，含批次、来源修订、原始轮标识及每题转换后的 v2 `unit`、逐题 revision、seed、候选引用和所属轮次。转换前的原始文件和 converter 复现信息通过其随附清单关联。
- **S3 逐题验证台账 `s3-validation.json`** 由已确认的 S3 签发方提供。含 `issuer_id` 和 `bindings`，绑定条目记录六元组、`status=PASS/FAIL` 与 `validation_round`。原始三态、校准、失败归档和凭证原件保存在 S3 正式报告。出站映射以及递补血缘随包提交。
- **S4 历史登记快照 `accepted-validation-ids.json`** 由 S4 运营受控维护，按签发方索引。接收时从已登记批次汇总导出并固定文件摘要，由独立路径交给核对器。首次空登记须有受理人核认。三份台账的 SHA-256 均由各自授权来源或其可信清单独立提供。核对器只读取工作区里的明确文件，结果留在 S4 受控接收记录。

正式候选集合须对应权威候选台账和实际 PASS。原轮分母取原轮权威候选及 S3 判定，递补单列。核对器要求递补链接回指原始失败，匹配同 seed、候选引用和独立 PASS，拒绝循环和重复计入。业务若需允许跨原始失败链或调整最终通过范围，应先固定规则，再用相应正反例核验。

### 离线运行与拒收证据

在 S4 仓库根目录运行，文件和摘要均使用真实受控输入。CLI 的非零退出表示拒收，JSON 只包含结果和错误码。成功表明逐题数据一致性核对通过，实际 S3 签发、报告有效性、校准及正式放行另循业务验收。

```powershell
$env:PYTHONPATH = (Resolve-Path '.\backend\src').Path
.\.venv\Scripts\python.exe -m openkb_s4.s3_binding_check `
  --envelope 'submission.json' `
  --candidates 'candidates-freeze.json' --candidates-sha256 '<S2来源的摘要>' `
  --verification 's3-validation.json' --verification-sha256 '<S3来源的摘要>' `
  --history 'accepted-validation-ids.json' --history-sha256 '<S4登记快照的摘要>'
```
