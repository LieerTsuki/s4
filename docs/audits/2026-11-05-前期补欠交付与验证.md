## 3. B05代码的实际行为

新API位于`/api/s4/v2/profile-revisions`：运营创建和修改DRAFT、提交REVIEW；auditor按会话身份独立批准APPROVED；运营或auditor可将已批准版本RETIRED。创建/编辑/提交贡献者的真实person_id均不得自批，多个账号同一person_id不能绕过。状态写入使用expected_revision和同scope锁，提交后快照不可编辑，停用后不能被新计划/新轮选择。

模型增加两张索引表`v13_profile_revisions`/`v13_profile_events`，批次增加nullable的配置/审批/手册/词表引用。正文、理由与签名依据均封入受控对象；DB保留索引、引用、摘要与必要身份信息。旧0006批次保持原baseline哈希及语义，不把旧v1批准迁移成新批准。

前端“当前任务配置”增加生命周期操作；“全量与观测对账”建队时可选择本数据集APPROVED配置；任务只读折叠区显示本批冻结指南正文与摘要。历史退休不改原批指南；正文缺失/篡改或当前执行核心与冻结Schema/量表不一致，返回409要求明确升级，不悄悄套新规则。

批准后的配置仍`formal_enabled=false`，D6/SEC完整字典未取得也不由本地表单自行批准。新批准快照、手册、词表和审批引用进入过程报告及原始证据引用图，导出前校验，备份与恢复按`v13_*` JSON `*_ref`动态发现。
