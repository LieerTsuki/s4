# v1.3 implementation contract

User instruction: implement the requirements indexed by `liyue/document/00_v1.3执行入口与文档索引.md` in this existing s4 directory. This implements the supplied 08 V2.0 design, with 01 V0.7, 07 V3.0 and 09 V1.0 as detailed requirements. Official source files remain read-only; no source Excel, old pipeline, external messaging or publishing is involved.

## Chosen boundaries

- Versioned `/api/s4/v2` adds index-only v1.3 imports, full VERIFICATION tasks and separate OBSERVATION batches. Authentication remains the existing session/CSRF mechanism. Legacy contracts and sealed records retain their original meaning.
- Source/material/gold/working and submitted bodies are private content-addressed UTF-8 files. DB records contain references, hashes and necessary operational indexes. Seal files before publishing references in a transaction. Verify digests on every read; reconcile orphans rather than deleting sealed history.
- Every valid imported unit needs its own human VERIFICATION record. OBSERVATION uses deterministic dataset/difficulty sampling, fixed independent people, BLIND group barrier and separate counts. A high kappa never supplies missing verification records.
- Review v3 separates gold relevance 3/2, ranking 1/0 and strict boolean expected_refusal/controlled absence_reason. Difficulty is easy/medium/hard. Thirteen types include D4C, D6 Unicode entities/relations, D7 human same-intent/max K and typed security materials.
- Kappa NORMAL/EXPAND_CALIBRATE/RETURN_TO_S2/UNDEFINED is observational. Low values permanently prevent the failed scope's handoff; new regenerated scope has lineage. J1/C1 and missing specialized definitions are explicit formal blockers, not switches that forge external approvals.
- S4 v2 outputs N candidates, N verification records, n observation units/IAA, report, quality actions and manifest. It does not produce or pretend to replace S5's final six-file package. Formal external contracts and real acceptance remain unaligned.
- PostgreSQL remains the local operational index during this migration. SQLite main-repo table mapping, builder/typer/GitLab integration require actual upstream schema/code. Record this ADR and provide an adapter boundary without inventing SQL columns or claiming integration.

## Verification and rollout

Tests must exercise full N vs n accounting, strict fields, specialized invalid material, object isolation, first-blind exposure, both release barriers, immutable/idempotent submissions, draft conflicts, return/policy blockers, content hashes, handoff set reconciliation and recovery. Retain and run legacy regression tests in their explicitly scoped compatibility environment. New browser checks demonstrate actual v3 three-column task flow. Production/local active DB migration requires a verified backup and isolated rehearsal before a maintenance window; no automatic old-label conversion.

## Work ownership

1. Domain/contracts: strict v1.3 validation, sampling, kappa, synthetic fixtures.
2. Workflow: index models/migration, real dual-track API, independence, revision/issue actions.
3. Frontend: current v1.3 operational routes and task forms; legacy history visibly separate.
4. Integration: controlled store, versioned router/OpenAPI, v2 handoff/backup, local CI/ADR and fresh evidence.

Unreceived D6 vocabulary, SEC controlled vocabulary, authoritative DB mapping, external protocol sign-off and human acceptance are tracked dependencies. Code must expose their effect rather than pre-fill approval.
