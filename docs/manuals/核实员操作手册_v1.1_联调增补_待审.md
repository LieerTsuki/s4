# 核实员操作手册v1.1联调增补（待审）

日期：2026-11-08。与[完整v1.0操作稿](核实员操作手册_v1.0_待审.md)合用，本文件补实际联调中的入口、阶段、材料和异常说明，不重复整本14章。状态为待审修订稿；没有正式发布批准，也没有T0真人分歧数据，因此不冒称完成原11/6“根据T0实战定稿v1.1”的验收。

## 1. 哪个阶段能看到三栏

| 页面状态 | 现在应做什么 | 可见内容 |
|---|---|---|
| 独立判断/BLIND/OPEN | 只按授权材料完成本人判断与理由，核对后由本人提交封存 | 题目、原文及适用ACL/时效、本人草稿；无模型答案/等级/S3结论 |
| 草案比对/REVIEW/OPEN | 比对本人封存与草案，逐点/逐文档/拒答或专项判定 | 普通QA三栏及本人独立记录；仍无对方标签/κ |
| 已封存/SEALED | 查看本人原始记录；需要改动时联系运营走修订/新轮 | 原记录只读；不能覆盖签名或用新标签改原κ |

主核实在本人相关同源族独立记录封存后释放；观测须固定A/B整个统计批全部独立封存，再由运营统一释放。看不到草案时先核对阶段与屏障，不为了让页面显示三栏而随便填写答案或请别人代封存。

## 2. 本轮7题怎样找到、怎样计数

用运营提供的有效预览入口登录本人账号→“我的核实任务”→“全量核实”→找到QAD1-0015—QAD1-0021→“进入作业”。本轮这些题只分配到ann-a演示身份，其他账号看不到相应任务是预期权限行为。

当前均为demo、独立阶段、待人工处理；不能在汇报中写成人工通过7题或T0已完成7/60。测试身份与真正核实人员的对应、资格、暴露历史和可用工时须另行确认。看过完整JSON、草案或诊断答案的人不能当本来源首次盲答员。

本轮只送审7个主问题。诊断中“11条改写已文本审查”不是已收到11个改写任务；没有题面、ID/母题和验证状态时不自行扩题。

## 3. demo诊断报告和答案草案怎么保管

原始JSON和诊断报告含答案或模型判断，由运营受控归档。`s3_report=null`可以用于demo联调，不能手动填PASS或accepted=true来让它看起来已经正式放行。当前诊断zip原件尚缺，包内路径/hash只作索取线索，不记“原件验收完成”。

独立阶段不经群聊、共享附件或下载另发完整包给核实员。授权原文本身允许包含答案句；平台隐藏的是生成草案和预先标出的等级/模型结论，不删去解题所需原文。

## 4. 401、403、404和草稿冲突怎么处理

| 现象 | 先做的检查 | 处理 |
|---|---|---|
| 打开预览就只有Unauthorized | 是麦芽预览签名过期，还是S4登录页已打开 | 向运营取得有效入口；不在手册/群聊长期保存签名或密码；不靠反复提交密码解决预览401 |
| 页面能开但会话失效 | 当前登录身份与会话 | 本人重新登录；仍失败记录时间/安全错误码交运营 |
| 403 | 当前角色是否允许访问运营来源/报告 | 核实员走“我的核实任务”，不要索取管理员会话 |
| 对他人任务404 | 是否确为本人分配 | 不修改ID尝试读取别人内容；分配错误交运营处理 |
| 草稿409 | 多窗口版本是否过期 | 先保留本人未提交输入、刷新核对服务器版本后合并；不覆盖已封存结果 |

异常只记录时间、任务ID、阶段、错误码/request_id及脱敏截图；不要在问题单贴密码、Cookie、CSRF或带签名地址。

## 5. 小总体观测不足怎么报

7题若后续建观测，按当前规则要求8、最多全取7、缺1；不能复制一题或塞入未经确认的改写凑数。当前尚未建观测，因此实际n=0；“8/7/缺1”是抽样规则/干跑说明，不是已完成观测结果。

主核实与观测人手分开。主核实V、固定观测A/B至少3名不同合适人员，实质修订还要留独立于编辑者的复验安排。两个账号不等于两名真实人员，身份或暴露未知时联系运营。

## 6. 原始文件摘要为什么可能与对象摘要不同

运营接收时分别记录原文件字节SHA256、实际传输SHA256、规范化对象与每题content_revision。空白/BOM/换行或数值0.0→0都可能改变摘要口径；不可仅凭hash不同就改题，也不可不调查就略过差异。

11/8本次已逐题回读，唯一差异是接收脚本数值表示变化，原题/草案/原文/诊断未发现其他变化。后续需要保留原始数值表示时直接发送原UTF-8 JSON字节，不先解析重序列化。相同batch_id+source_revision异内容冲突时先停查，不擅自改来源号绕过。

## 7. 版本和正式状态

11/8麦芽实测0006，本地新增配置功能要求0007。手册附录B的配置生命周期不能据本地实现就认定麦芽已上线；升级须以实际部署、恢复和权限回归为准。API的认证/人员仍在v1，任务/业务在v2，过程Schema为review.v3，三者版本号不同是正常设计。

本轮候选源码另补了审批页只读详情：在待审行展开“查看配置内容 · 数据集 · 版本”，核对记录版本、手册、摘要、操作说明、指南正文及完整配置快照，确认实际内容后再签名批准。审批员没有编辑入口；不得只看hash就声称已审正文。该控件仍属本地候选，麦芽未部署。
