## 2 UNDETERMINED 与分母

1. S3 原始报告记录 `PASS`、`FAIL`、`UNDETERMINED`。`raw_checked = raw_passed + raw_failed + raw_undetermined`，`raw_pass_rate = raw_passed / raw_checked`。已在正式范围内完成检查、仍无法判为 PASS 的单元留在分母。
2. 出站 v2 `s3_report.checked = raw_checked`，`passed = raw_passed`，`failed = raw_failed + raw_undetermined`，`pass_rate = raw_passed / raw_checked`。逐题 `UNDETERMINED` 投影为 `FAIL`，其题号进入 `failed_ids`，原始三态及 `S3_UNDETERMINED_*` 原因归档在 S3 证据中。v2 严格对象使用定义中的字段，原始 `report_profile` 和 `undetermined` 存在独立原件。
3. 批次中断、输入不齐、服务故障或校准未绑定时，运行记 `RUN_INCOMPLETE`，不产生正式出站报告。批次启动前的范围清单保留排除对象和理由。
4. 通过率以 0–1 表示，原始分母门槛为 `passed / checked ≥ 0.90`，按未舍入比例判断。最终 `units` 只含具备有效 PASS 的当前版本，原始失败题及被投影为失败的题不得进入最终集合。
5. 递补独立记录轮次、原失败和新候选关联、同种子依据及新 PASS。原始计数和通过率始终来自原始轮次。无递补时出站 `replacements: []`，原报告记录 `replacement_occurred=false` 和 `NO_REPLACEMENT_OCCURRED`。

| 原始 checked / PASS / FAIL / UNDETERMINED | v2 checked / passed / failed | v2 pass_rate 与判定 |
|---|---|---|
| 10 / 8 / 1 / 1 | 10 / 8 / 2 | `0.8`，预检拒绝 `S3_RETURN_TO_S2` |
| 10 / 9 / 0 / 1 | 10 / 9 / 1 | `0.9`，原始通过率达标，未判定题归档，最终逐题 PASS 仍须核对 |
| 批次运行中断 | 无正式投影 | `RUN_INCOMPLETE`，等待该批有效报告 |

## 4 revision 与摘要绑定

- `source_revision` 指向本批实际生成的已冻结来源快照。`unit_id` 是稳定题号，`unit_revision` 标识该题实际待审版本。最终候选清单由来源侧先固定逐题 revision。题面、草案、证据原文或影响验证的内容修订后，登记新 `unit_revision`，由 S3 为新内容复验并签发可追溯的 `validation_id`。保留旧报告和原失败。
- 正式交接按 `(batch_id, source_revision, unit_id, unit_revision, content_sha256, validation_id)` 逐项对账。v2 信封承载批次和来源，`unit_results[]` 承载题号、结论、摘要和验证 ID。逐题 revision 及六项关联从独立、随包可验证的候选和验证台账取得。`unit_results` 严格对象不接受新增 `unit_revision` 或嵌套 `batch_id`。具体附表字段名、签发身份与 ID 唯一域由双方签认后引用。
- 当前 S4 工作台 `content_revision` 的可复算基线为 `canonical_sha256(validate_envelope(payload)["units"][i])`。先核 context 原文摘要，再用固定 Schema/运行时做规范化。规范化包括省略模型的 `None` 字段、保留默认值、补算 `contexts[].sha256` 和移除旧 `match_field`。取单个完整规范化 unit，以 Python `json.dumps(ensure_ascii=False, sort_keys=True, separators=(",", ":"), allow_nan=False)` 生成 UTF-8 再做 SHA-256。数组顺序保留。随包首题规范化向量为 716 字节，SHA-256 `859d7e180a468377d926fe3e3bac5f31827b2df6b05b6fdec43817abf3d61165`。建议将该基线用于本批 PASS 绑定，由 S3 确认相同规范化和字节向量后固化。原始文件、原文文本、单元和整包的摘要分别留档。
- 相同 `batch_id + source_revision` 的等内容导入由现行服务幂等处理，异内容返回 `409 SOURCE_REVISION_CONFLICT`。逐条 PASS 和 `validation_id` 的重发、异绑定冲突、错种子、循环或重复抵扣目前须按原件和独立台账复核。待双方确认后，以合法递补接收及六种语义反例拒收完成新版联调。
